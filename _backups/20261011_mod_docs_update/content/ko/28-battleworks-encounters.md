## 이번 실습의 목표

추가 마법 모드 없이 **베기·찌르기·후퇴를 쓰고 체력 50%에서 강화 공격을 추가하는 검사 보스**를 만듭니다. 수치는 구조를 이해하기 위한 시작값입니다. 완성 전 실제 플레이로 난이도를 조정합니다.

준비물은 [첫 공격 실습](#mob-editor/battleworks-first-attack)을 마친 일반 인간형 NPC입니다.

## 1. 작업 파일 분리하기

1. 기존 첫 공격을 Load합니다.
2. **Save As → bosses/training_captain.json**으로 저장합니다.
3. CustomNPCs에서 최대 체력을 `100`으로 준비합니다.
4. 일반 공격·마법을 담당하는 기존 스크립트가 함께 움직이지 않는지 확인합니다.
5. 전투를 시험할 생존 플레이어와 장비를 일정하게 유지합니다.

원본 first_sword 파일을 보관하면 문제가 생겼을 때 정상 동작과 비교할 수 있습니다.

## 2. 패턴 구성표 만들기

| 패턴 | 시작 거리 | Windup / Action / Recovery | 역할 |
| --- | --- | --- | --- |
| 전방 베기 | 0~2.7 | 24 / 16 / 24 | 기본 공격 |
| 전방 찌르기 | 0~3.2 | 28 / 16 / 24 | 조금 긴 전방 공격 |
| 짧은 후퇴 | 0~2.0 | 6 / 12 / 12 | 가까이 붙은 타겟과 거리 벌리기 |
| 강화 베기 | 0~2.7 | 18 / 16 / 20 | 2페이즈에서 추가할 공격 |
| 분노 시작 | 넉넉한 거리 범위 | 0 / 30 / 10 | 체력 50% 전환 연출 |

거리 밖에서는 Chase Target가 접근하도록 합니다. 먼 거리에서 공격하는 패턴이 없다면 접근 가능한 지형이 필요합니다.

## 3. 베기와 찌르기부터 안정시키기

1. 첫 공격의 베기를 그대로 둡니다.
2. [히트박스 실습](#mob-editor/battleworks-hitboxes)의 Box를 만들고 찌르기 Action에 연결합니다.
3. 찌르기 피해도 우선 `4`로 맞춥니다.
4. 찌르기 Hitbox 이벤트를 Action `3틱`에서 시작해 모션에 맞춥니다.
5. 두 공격 Priority를 `10`, Base Score를 `10`으로 맞춥니다.
6. 두 공격을 모두 볼 때까지 가까운 거리에서 반복 시험합니다.

이 단계에서 한 공격만 나온다면 새 페이즈를 만들기 전에 거리·점수·쿨다운을 해결합니다.

## 4. 짧은 후퇴 섞기

1. [이동 안내](#mob-editor/battleworks-movement)에 따라 Action의 Away `0.08`, 12틱 후퇴 패턴을 만듭니다.
2. Mobility를 켜고 Role을 알아보기 쉽게 이동용으로 구분합니다.
3. 처음에는 피해를 넣지 않습니다.
4. Base Score를 `6` 정도로 두고 공격보다 덜 자주 선택되는지 봅니다.
5. 후퇴가 끝난 뒤 추적이 복귀하는지 확인합니다.

너무 자주 후퇴하면 Base Score나 거리 범위를 줄입니다. 이동만 반복한다면 실제 공격이 거리 조건을 통과하는지 먼저 봅니다.

## 5. 2페이즈 추가하기

1. [페이즈 안내](#mob-editor/mob-editor-phases)에 따라 1페이즈 100%, 2페이즈 50%를 만듭니다.
2. 강화 베기는 별도 패턴으로 만들고 Min Phase `2`로 제한합니다.
3. 기존 공격은 1~2페이즈에서 모두 허용합니다.
4. 강화 베기는 피해를 올리기 전에 Windup을 `24 → 18`로 줄여 차이를 시험합니다.
5. 너무 빠르다면 20~24틱 사이에서 조절합니다.

피해·속도·공격 횟수를 동시에 올리면 초보 플레이어가 반응하기 어렵습니다. 한 가지 차이부터 확인합니다.

## 6. 분노 시작 연출 연결하기

1. “분노 시작” 패턴에 Action 0틱 Title과 Sound를 추가합니다.
2. 2페이즈를 허용하고 일반 트리거 Manager를 유지합니다.
3. 전환 전용으로 쓰려면 Base Score와 다른 가산점을 모두 0으로 둡니다.
4. 2페이즈의 Transition Pattern에서 이 패턴을 선택합니다.
5. 체력을 50% 아래로 내려 한 번 실행되는지 봅니다.
6. 회복해도 페이즈가 내려가지 않는지 확인합니다.

화면 경고만으로 전환을 알기 충분하면 별도 마법이나 팝업 없이도 완성할 수 있습니다.

## 7. 선택적으로 패시브 하나 추가하기

“화살에 맞으면 후퇴”를 원하면 [원거리 피격 패시브](#mob-editor/battleworks-passives)를 추가합니다. 일반 후퇴 패턴 자체를 패시브로 바꾸면 Manager 후보에서 빠지므로, 일반 후퇴와 피격 후퇴를 둘 다 원할 때는 별도 패턴을 사용합니다.

Queue 패시브는 기본적으로 현재 공격이 끝난 뒤 실행을 기다립니다. 즉시 피해 취소가 필요한 방어는 별도 고급 트리거입니다.

## 8. 선택적으로 바닥 경고 추가하기

[Particle Maker](#mob-editor/battleworks-particles)에서 원형 예고를 만들고 Windup에 연결합니다. 파티클은 피해가 없으므로 실제 Hitbox와 반경·타격 시점을 함께 맞춥니다.

플레이어의 **이전 위치**에 지연 공격을 하려면 현재 Target를 계속 따라가는 원 대신 [위치 저장 → 예고 → 저장 위치 판정](#mob-editor/battleworks-advanced-actions)을 사용합니다.

## 9. 거리와 상황별 최종 시험

| 상황 | 확인 결과 |
| --- | --- |
| NPC와 약 1블록 | 베기·후퇴가 모두 가능한지 |
| 약 2.5블록 | 근접 모션과 실제 피해가 맞는지 |
| 약 3블록 | 찌르기 또는 재접근이 나오는지 |
| 약 6~8블록 | 추적 후 공격으로 연결되는지 |
| 벽 뒤·계단 | 시야와 높이 조건, 길찾기가 자연스러운지 |
| 체력 50% 전후 | 전환과 강화 공격이 동작하는지 |
| 전투 중 회복 | 페이즈가 되돌아가지 않는지 |
| 타겟 상실 후 재전투 | 전투 상태 초기화가 의도대로 되는지 |
| NPC 처치 | 사망 연출·BGM 종료·소환 정리가 필요한지 |

## 10. 배포용으로 정리하기

작업 파일을 다시 Load하여 변경 내용이 남아 있는지 확인합니다. 사용하는 전투 JSON, 파티클 JSON, 모델·사운드·팝업, 외부 모드 요구사항을 함께 정리합니다. 샘플 제작 기록만으로 자동 설치되는 자료라고 안내하지 마세요.

[저장·백업·샘플 안내](#mob-editor/battleworks-files)와 [문제 해결](#mob-editor/battleworks-troubleshooting)을 마지막으로 확인합니다.
