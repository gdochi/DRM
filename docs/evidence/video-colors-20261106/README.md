# 기존 GIF 변환 영상의 색상 교정과 재촬영

2026-11-06. 간호순 치료, DNPC 침대 지정, 레머넌트 메시지의 기존 GIF 변환 영상 3개를 실제 Minecraft에서 다시 촬영했다. GIF 팔레트가 줄인 색상을 그대로 영상으로 옮긴 것이 원인이었다. 예를 들어 기존 간호순 포스터는 55색이고, 같은 첫 화면의 새 원본은 185색이다. 녹색 제목·설명이 기존 파일에서 주황/갈색으로 합쳐졌으나 새 원본과 브라우저 영상에서는 구분된다.

## 촬영과 출력

- 별도 소유 인스턴스: `color-videos-neo1211-en-01`, NeoForge 1.21.1, 1280×720, 약 20fps. 기존 `three-short-gifs.json`의 실제 화면·서버 조작 계획을 사용했으며 수동 마우스 녹화로 표현하지 않는다. 사용자 월드와 모드 소스는 변경하지 않았다.
- 새 PNG 프레임은 간호순 704개, 침대 508개, 레머넌트 380개다. 95백분위 프레임 간격은 약 51~54ms, 최대 간격은 80ms 미만이며 저장 큐의 프레임 누락은 없다. [간격 기록](capture/cadence.json).
- 간호순의 치료 완료·복귀, 지정한 침대에서 실제 수면, 메시지 저장·읽기 결과를 서버 기록과 원본 화면으로 확인했다. [촬영 환경](capture/environment.json), [화면/조작](capture/screens.json), [확인 요약](capture/workflow-summary.json).
- 영상은 GIF를 거치지 않고 원본 PNG에서 직접 인코딩했다. 전체 범위 RGB에서 제한 범위 BT.709로 변환하고 MP4·WebM에 동일한 색 정보를 명시했다. PNG 포스터는 첫 원본과 RGB 픽셀이 일치한다. 각 영상 JSON에 입력·출력 해시·길이·크기를 기록했다.
- 새 자산: `src/media/guides/short-videos-color-20261106/`. 5개 본문 언어의 관련 문서 20곳과 `src/guide-environments.json`을 연결했다. 새 주소를 사용해 기존 파일 캐시와 구분한다.
- `scripts/encode-guide-video.py`는 원본 프레임을 기본으로 사용하며 GIF 입력은 명시적 `--allow-gif`를 요구한다. 일반 영상 3개나 다른 작업의 영상은 다시 인코딩하지 않았다.

## 색과 재생 확인

- [FFmpeg 디코딩 비교](decoded-color-results.json): 6개 영상의 첫 디코딩 프레임과 새 원본 비교. 평균 RGB 오차는 255단계 기준 약 0.88~1.68이다. 모든 포스터는 원본과 일치한다.
- [Chrome 실제 디코딩 비교](browser-colors/results.json): MP4·WebM 각각 1280×720에서 원본과 비교했다. 평균 RGB 오차는 약 0.78~1.14이며, 원본 녹색 픽셀의 녹색 계열 유지율은 약 94.7~95.4%다. 손실 압축과 색차 서브샘플링의 작은 오차까지 완전 무손실이라고 주장하지 않는다.
- 원본 대표 프레임과 Chrome 출력 화면을 직접 열어 녹색 안내 글자·금색 테두리, 침대 수면과 메시지 표시를 확인했다. 실제 시간대·화면 배경에 따른 조명과 어두워짐은 게임 원본 그대로다. 별도의 갈색/세피아 필터는 없다.
- `npm.cmd run build`, `npm.cmd run verify`, `npm.cmd run verify:translations` 통과. 문서 885개와 번역 531개를 확인했다.
- `npm.cmd run verify:videos`: [브라우저 결과](browser/results.json). 영상 화면 140개·고유 영상 11개에서 자동 재생, 무음, 탐색, 일시정지, 반복 경계, MP4 호환, 모바일 표시와 동작 줄이기 확인. JavaScript 오류 없음.
