## 화면을 읽는 순서

**Pattern Workbench**는 제작자가 패턴을 편집하는 화면입니다. 왼쪽에서 패턴을 고르고, Windup / Action / Recovery 중 단계를 고른 다음, 타임라인의 액션 행을 선택해 속성을 바꿉니다.

| 화면 / 도구 | 사용하는 때 |
| --- | --- |
| Pattern Workbench | 공격 조건과 세 단계, 실행 액션을 편집 |
| Hitbox Library | 재사용 판정의 모양·피해·위치와 모델 미리보기 |
| Combat Rules | 전투 규칙, Manager, Boss Phases, 사망 연출 |
| Particle Maker | 별도 시각 효과 파일 제작 |
| Pattern Build Assist | 질문에 답해 물리 공격의 시작 구조 생성 |
| Pattern Graph | 패턴과 콤보 연결 관계 확인 |
| Simulation | 선택 패턴의 움직임·모션·판정 위치를 재생 |

## 1. 패턴 선택하고 이름 바꾸기

1. **Find pattern**에서 패턴 이름이나 ID로 검색합니다.
2. 목록의 패턴을 클릭합니다. 액션 행을 클릭하기 전에 편집 중인 패턴이 맞는지 봅니다.
3. **Core**에서 Name을 알아보기 쉽게 지정합니다. “전방 베기”, “후퇴 후 찌르기”처럼 행동을 설명하는 이름이 편합니다.
4. Enabled와 Min Range / Max Range를 확인합니다.
5. **Score**에서 선택 선호도를, **Combo**에서 완료 후 연결할 패턴을 편집합니다.

ID는 파일 안의 참조에 사용됩니다. 이름만 바꾸는 것과 ID·연결을 바꾸는 것은 다릅니다. JSON에서 ID를 바꾸면 그 ID를 참조하는 콤보와 페이즈도 함께 고쳐야 합니다.

## 2. 단계 길이 정하기

| 단계 | 역할 | 느린 첫 공격의 예 |
| --- | --- | --- |
| Windup | 준비, 경고, 시선 맞추기 | 24틱 |
| Action | 실제 타격·스킬·이동 실행 | 16틱 |
| Recovery | 회복 동작과 반격할 틈 | 24틱 |

각 단계의 Ticks가 그 단계의 길이입니다. 패턴 Core의 **Recovery Delay**는 세 단계가 끝난 뒤의 추가 대기 기준이므로 Recovery의 Ticks와 다릅니다.

단계 길이를 줄였으면 그 안의 이벤트도 다시 확인합니다. Action을 10틱으로 줄이고 Event Tick을 12에 두면 범위 오류가 납니다.

## 3. 액션 한 개 추가하기

1. 예를 들어 **Action** 단계를 선택합니다.
2. **+ Action**을 누릅니다.
3. 목적에 맞는 상위 분류를 고르고 하위 액션을 선택합니다.
4. Hitbox라면 **Choose from list**에서 기존 히트박스를 고르거나 새로 만듭니다.
5. 타임라인의 해당 액션 행을 클릭합니다.
6. **Event Tick**을 `3`, **Interval**을 `0`, **Repeat Count**를 `1`로 둡니다.
7. 이벤트와 액션의 확률을 각각 `100`으로 두고 한 번 실행되는 상태부터 확인합니다.

상위 분류는 액션을 찾기 위한 메뉴입니다. 분류를 클릭하는 것 자체가 전투 기능을 켜는 스위치는 아닙니다. 하위 목록에서 상위 분류로 돌아가거나 Esc로 검색 범위를 다시 선택할 수 있습니다.

**+ Skill**은 스킬 선택을 빠르게 여는 버튼이고, **+ FX**는 사운드·타이틀·명령어 연출을 추가할 때 사용합니다.

## 4. 이벤트와 액션 행 구분하기

이벤트는 “Action 3틱에 실행할 것들”이라는 묶음입니다. 그 안에 Hitbox와 Sound를 함께 넣으면 두 액션이 같은 타이밍을 공유합니다.

| 바꾸는 값 | 영향 범위 |
| --- | --- |
| 이벤트의 Event Tick | 묶음 안의 모든 액션 실행 시점 |
| 이벤트의 Interval / Repeat Count | 묶음 전체의 반복 |
| 이벤트 확률 | 그 회차의 묶음 전체 실행 여부 |
| 개별 액션의 Chance | 그 액션만 실행할 확률 |
| Hitbox 액션의 Damage Multiplier | 그 사용 위치의 피해 배율 |
| 라이브러리의 Damage | 같은 히트박스를 참조하는 모든 사용 위치 |

같은 틱의 액션도 타임라인에서는 이름 있는 별도 행으로 선택합니다. 사운드는 3틱, 타격은 8틱에 실행하고 싶다면 서로 다른 이벤트로 나눠야 합니다.

## 5. 핀과 재생 위치 조작하기

1. 액션 행의 **핀**을 드래그하면 그 이벤트의 실행 시점이 바뀝니다.
2. 눈금이나 빈 트랙을 클릭·드래그하면 미리보기의 재생 위치가 바뀝니다.
3. 액션이 많으면 타임라인을 스크롤합니다.
4. 현재 선택한 단계와 Event Tick 값을 함께 확인해 잘못된 단계를 수정하지 않았는지 봅니다.

예를 들어 Windup 24틱 다음의 Action 3틱은 전체 눈금에서 27틱 위치에 해당합니다. JSON의 `at`와 Event Tick은 **현재 단계 안의 시간**입니다.

## 6. 반복 공격 만들기

Action을 `20틱`으로 두고 이벤트를 다음처럼 설정합니다.

| 값 | 입력 |
| --- | --- |
| Event Tick | 4 |
| Interval | 6 |
| Repeat Count | 3 |
| 실행 시점 | Action 4, 10, 16틱 |

마지막 실행 시점은 다음 식으로 계산합니다.

```text
첫 시점 + 간격 × (횟수 - 1) ≤ 단계 길이
4 + 6 × (3 - 1) = 16 ≤ 20
```

Repeat Count는 **첫 실행을 포함한 총횟수**입니다. Interval 0은 반복 없음입니다. 반복 판정을 추가해도 애니메이션이 매번 처음부터 재생되는 것은 아닙니다. 같은 대상에게 어느 정도 자주 피해를 허용할지는 [히트박스의 반복 판정 정책](#mob-editor/battleworks-hitboxes)에서 별도로 정합니다.

## 7. 확률은 한 곳부터 조정하기

처음에는 모두 100%로 두세요. 타격은 항상 나가고 대사만 가끔 나오게 하려면 이벤트 100%, Hitbox 100%, 대사 액션 20%로 설정합니다.

이벤트 50% 안의 대사 액션 20%는 단순 기본 확률 기준으로 `0.5 × 0.2 = 10%`입니다. 고급 체력·페이즈 확률 보너스와 조건까지 설정하면 실제 실행 빈도가 추가로 달라집니다.

## 8. 패널이 좁거나 사라졌을 때

- 패널 사이 구분 막대를 드래그해 목록·작업 영역·속성 폭을 조절합니다.
- Hitbox Library에서는 모델과 타임라인의 높이, 모델과 Clips의 폭도 조절합니다.
- 패널 제목의 방향 화살표로 접고 펼칩니다.
- **Reset panels**로 기본 배치를 복원합니다.
- Simulation 창은 제목 부분을 끌어 이동하고 오른쪽 아래 손잡이로 크기를 바꿉니다.

미리보기 속도 `0.1x~4.0x`는 관찰 속도입니다. 느리게 재생해도 저장한 Ticks 값이 늘어나지 않습니다. 패널 배치는 클라이언트 설정에 저장되며 NPC 전투 수치와 별개입니다.

## 저장 전 확인

1. 선택 패턴과 문서가 Enabled인지 확인합니다.
2. 비어 있는 Skill ID나 끊긴 Hitbox 참조가 없는지 봅니다.
3. 마지막 반복이 단계 길이를 넘지 않는지 계산합니다.
4. 오류를 해결하고 Save 또는 Save As로 저장합니다.
5. NPC에 적용해 실제 공격을 확인합니다.
