## 조우 전체 흐름

Trainer의 조우는 단순히 “범위 안이면 전투”로 끝나지 않습니다. 자동 조우는 다음 상태를 순서대로 거칩니다.

```text
대상 검색 → 대상 예약 → 감지 연출 → 반응 대기 → 선택형 추적
→ 전투 요청 → 라운드·쿨다운·조건 검사 → 배틀 연출
→ 최종 조건 검사 → Cobblemon 배틀 → 결과·보상·진행도 기록 → 복구
```

한 NPC가 대상을 예약하면 다른 플레이어가 그 NPC를 동시에 사용할 수 없습니다. 플레이어도 다른 트레이너 조우에 중복 예약되지 않습니다.

## Trigger

| Trigger | 시작 조건 | 적합한 용도 |
| --- | --- | --- |
| `Interaction` | 양손이 빈 플레이어가 Main Hand로 NPC를 우클릭하고 확인 화면에서 수락 | 대화형 트레이너, 체육관 관장, 기본 테스트 |
| `Vision` | 플레이어가 거리·NPC 정면 반각·선택형 Line of Sight를 통과 | 눈이 마주치면 반응하는 길거리 트레이너 |
| `Radius` | 플레이어가 NPC 중심 반경 안에 들어옴 | 경비병, 보스 방, 방향과 벽을 무시하는 범위 조우 |

`Vision`과 `Radius`는 확인 화면을 거치지 않고 감지·반응·추적 흐름을 통해 서버가 전투 시작을 시도합니다. `Interaction`은 감지 마커와 자동 추적을 사용하지 않습니다.

## 자동 감지에서 제외되는 플레이어

Vision과 Radius는 다음 플레이어를 후보에서 제외합니다.

- 크리에이티브 모드
- 관전자 모드
- 사망했거나 제거된 플레이어
- NPC와 다른 월드에 있는 플레이어
- 이미 Cobblemon 배틀 중인 플레이어
- 다른 트레이너가 예약한 플레이어
- 현재 NPC와 이미 연출 또는 전투 중인 플레이어
- 재대전 횟수를 모두 사용한 플레이어
- 쿨다운이 남은 플레이어
- 현재 선택될 라운드의 조건을 만족하지 못한 플레이어

후보가 여러 명이면 유효한 후보 중 NPC와 가장 가까운 한 명을 선택합니다. 자동 감지 조건은 대상 선정 때 검사되지만 실제 배틀 시작 직전에도 다시 검사됩니다.

## 감지 설정

| 설정 | 범위 | 실제 의미 |
| --- | ---: | --- |
| `Detection interval` | 5–200틱 | 새 대상을 검색하는 주기입니다. 20틱은 약 1초입니다. |
| `Vision distance` | 1–64블록 | Vision 후보가 될 수 있는 최대 거리입니다. |
| `Vision half-angle` | 5–180도 | NPC 정면에서 좌우 각각 허용하는 각도입니다. |
| `Detection radius` | 1–64블록 | Radius가 검색하는 반경입니다. |
| `Line of Sight` | On/Off | Vision에서 블록에 가려지지 않고 실제로 보여야 하는지 정합니다. |

Vision의 반각이 35도라면 전체 시야 폭은 약 70도입니다. 180도는 정면 판정이 사실상 전 방향이 되지만 Line of Sight를 켜면 벽 뒤 대상은 여전히 제외됩니다.

Radius는 시야각과 Line of Sight를 사용하지 않습니다. 벽 너머 감지가 싫다면 Vision을 사용하거나 반경과 NPC 배치를 조정하세요.

한 번 대상을 잡거나 시작에 실패한 직후에는 내부 재시도 지연이 적용됩니다. 실패한 NPC가 매 틱 대상을 다시 잡아 마커와 경로 탐색을 반복하지 않도록 하는 보호입니다.

## Detection FX

감지 연출은 Vision 또는 Radius가 새 플레이어를 획득할 때 한 번 실행됩니다.

| 설정 | 범위·동작 |
| --- | --- |
| `Marker Text` | 최대 32자입니다. 줄바꿈은 제거됩니다. `!`, `...`, 짧은 대사를 사용할 수 있습니다. |
| `Marker Color` | `#RRGGBB` 또는 `#AARRGGBB` |
| `Scale` | 0.25–4.0 |
| `Y Offset` | 0–3블록, NPC 머리 위 표시 높이 |
| `Display Distance` | 4–256블록, 클라이언트가 마커를 표시할 거리 |
| `Hold Ticks` | 대상 해제 후 0–600틱 유지 |
| `Sound` | 등록된 Minecraft Sound ID |
| `Sound Volume` | 0–4 |
| `Sound Pitch` | 0.05–4 |
| `Reaction Ticks` | 1–200틱, 마커·사운드 뒤 다음 행동 전 대기 |

Reaction Ticks 동안 NPC는 즉시 달리지 않습니다. 대기가 끝났을 때 Chase가 꺼져 있으면 그 자리에서 전투 시작을 시도하고, Chase가 켜져 있으면 추적으로 전환합니다.

## Chase

| 설정 | 범위 | 실제 동작 |
| --- | ---: | --- |
| `Chase` | On/Off | 감지 후 플레이어를 따라갈지 정합니다. |
| `Walking Speed` | 0–100 | CustomNPCs 이동 속도 스케일입니다. 내부 내비게이션 배수는 `값 ÷ 5`입니다. |
| `Stop Distance` | 0.5–8블록 | 플레이어에게 충분히 접근했다고 판단하는 거리입니다. |
| `Max Distance` | Stop Distance 이상, 최대 96블록 | NPC와 대상 플레이어의 현재 좌표 사이에 허용되는 최대 추격 거리입니다. 서버가 매 틱 두 엔티티의 현재 위치로 다시 계산합니다. |
| `Duration` | 10–1200틱 | 반응 단계가 끝난 뒤 추적을 유지할 최대 시간입니다. |
| `Return Home` | On/Off | 실패·취소 후 감지 당시 홈으로 돌아갈지 정합니다. |

### Stop Distance 판정

NPC가 한 틱만 Stop Distance 안에 스쳤다고 바로 전투를 시작하지 않습니다. 짧은 흔들림을 막기 위해 가까운 상태가 여러 틱 연속 유지되어야 합니다. 소스 기준으로 4번 연속 만족해야 하며, 다시 멀어졌다고 판단하는 경계에는 약 0.5블록의 여유가 있습니다.

### 추적 종료 조건

다음 상황에서는 전투 요청 전에 추적이 실패하거나 취소될 수 있습니다.

- 대상이 로그아웃·사망·제거됨
- 대상이 크리에이티브·관전자 상태가 됨
- 대상이 다른 Cobblemon 배틀에 들어감
- 플레이어 또는 NPC 예약 상태가 바뀜
- NPC와 대상 플레이어의 현재 거리가 Max Distance보다 멀어짐
- Duration 초과
- 경로 탐색으로 Stop Distance에 도달하지 못함
- 재대전·쿨다운·라운드 조건이 더 이상 허용하지 않음

`Return Home`이 켜져 있으면 NPC는 감지 당시 홈으로 복귀합니다. 복귀는 도착하거나 내부 안전 제한인 1200틱을 넘으면 종료됩니다.

감지 당시 캡처한 홈 좌표는 복귀와 Battle Positioning에만 사용됩니다. Max Distance 판정에는 홈 좌표를 사용하지 않습니다.

## Battle Positioning

Battle Positioning은 배틀 화면의 포켓몬 위치가 아니라 월드에 있는 플레이어와 CustomNPCs NPC의 시작 위치를 정리하는 기능입니다.

| 설정 | 범위 | 기능 |
| --- | ---: | --- |
| `Battle Positioning` | On/Off | 연출 전과 실제 배틀 시작 직전에 위치·방향을 맞춥니다. |
| `Player Distance` | 1–16블록 | NPC 앞에 플레이어를 놓을 목표 거리입니다. |

서버는 감지 또는 상호작용 시점의 NPC 홈 좌표와 회전을 캡처합니다. 정렬할 때 NPC는 홈 중심과 약간 높은 Y 위치로 맞추고, 플레이어를 NPC 앞에 배치한 뒤 서로 바라보게 합니다.

플레이어 자리가 블록과 충돌하면 정면만 고집하지 않고 좌우 각도와 높이를 바꾼 후보 위치를 순서대로 시험합니다. 완전히 안전한 자리를 찾지 못해도 서버는 경고를 남기고 가능한 상태에서 다음 검증을 진행할 수 있으므로 좁은 방·낮은 천장·절벽에서는 반드시 실전 테스트가 필요합니다.

위치 정렬은 두 번 실행됩니다.

1. Battle Presentation을 보내기 전
2. 연출과 시작 지연이 끝나 실제 Cobblemon 배틀을 시작하기 직전

연출 중 밀치기나 이동으로 위치가 틀어져도 시작 직전에 한 번 더 맞추기 위한 동작입니다.

## 전투 중 트레이너 NPC

Trainer NPC는 전투가 시작돼도 숨지 않습니다. 대신 전투 전부터 종료까지 다음 상태로 잠깁니다.

- 수평 위치 고정
- 상대 플레이어를 바라보도록 시선 갱신
- 내비게이션과 공격 대상 제거
- 무적 상태 적용
- 체력이 잠금 당시 값 아래로 내려가지 않도록 보호
- 공격·피격·사망 시도 차단
- 다른 플레이어의 중복 사용 차단
- 첫 상대 포켓몬의 Poké Ball을 손에 표시

승리·패배·도주·시작 실패·서버 종료 정리에서 잠금을 해제하고 원래 무적 상태와 체력, 볼 표시를 복구합니다.

`Pokemon Itself`는 동작이 다릅니다. 전투용 Cobblemon 포켓몬 엔티티를 따로 만들고 CustomNPCs NPC를 임시로 숨긴 뒤, 전투가 끝나면 NPC 표시를 복구합니다.

## 연출 대기와 최종 검증

서버는 Battle Presentation Duration과 현재 라운드의 Start Delay를 더한 시각을 배틀 시작 예정 시각으로 잡습니다. 대기 중에는 NPC와 플레이어를 예약하고 Trainer NPC를 잠급니다.

대기 중 다음 상황이면 안전 취소됩니다.

- 플레이어나 NPC가 사라짐 또는 사망
- 서로 다른 월드로 이동
- 플레이어가 NPC에서 16블록보다 멀어짐
- 클라이언트 연출이 `missing_player`, `missing_target`, `interrupted`로 끝남

예정 시각이 되면 서버는 다시 검사합니다.

1. 플레이어와 NPC 유효성 및 16블록 이내 거리
2. 플레이어가 다른 배틀에 들어가지 않았는지
3. 연출 전에 잡아 둔 선두 포켓몬을 여전히 사용할 수 있는지
4. 현재 라운드 조건을 여전히 만족하는지
5. Battle Positioning 재정렬

하나라도 실패하면 배틀을 시작하지 않고 예약·잠금·볼 표시를 복구합니다.

### 연출 스킵

연출이 `Skippable`이고 플레이어가 스킵하면 서버는 원래 예정 시각을 기다리지 않고 즉시 최종 검증을 실행합니다. 남은 연출 시간과 Start Delay가 모두 생략됩니다.

스킵이 불가능한 연출에서 클라이언트가 임의로 스킵 결과를 보내도 서버는 계속 진행하지 않습니다.

## 첫 도전과 재대전

라운드 선택의 기준은 해당 플레이어가 해당 NPC를 승리로 클리어한 횟수입니다.

- 클리어 수 0: 항상 1라운드
- 패배: 클리어 수 증가 없음
- 도주: 클리어 수 증가 없음
- 승리: 클리어 수 1 증가
- 첫 승리 이후: Rematch 설정으로 다음 라운드 결정

패배나 도주 뒤에는 여전히 첫 라운드가 선택됩니다. 다만 전투 결과로 쿨다운이 시작될 수 있으므로 즉시 다시 도전하지 못할 수 있습니다.

## Rematch 설정

| 설정 | 실제 동작 |
| --- | --- |
| `Rematch Off` | 한 번 승리한 플레이어는 다시 도전할 수 없습니다. 패배·도주는 다시 도전할 수 있습니다. |
| `Max Rematches 0` | 최초 승리 이후 추가 승리 허용 없음 |
| `Max Rematches 3` | 최초 승리 + 추가 3승, 총 최대 4번 클리어 가능 |
| `Max Rematches -1` | 승리 횟수 제한 없음 |
| `Start Round` | 첫 승리 이후 첫 재대전에 사용할 라운드. UI는 1부터 표시합니다. |
| `Fixed` | 모든 재대전에서 Start Round만 사용 |
| `Continue` | Start Round부터 하나씩 올라가고 마지막 라운드에서 고정 |
| `Loop` | Start Round부터 마지막 라운드까지 반복 |

### 라운드 계산 예시

라운드 4개, Start Round 2일 때:

| 클리어 전 승리 수 | 도전 종류 | Fixed | Continue | Loop |
| ---: | --- | ---: | ---: | ---: |
| 0 | 첫 도전 | 1 | 1 | 1 |
| 1 | 첫 재대전 | 2 | 2 | 2 |
| 2 | 두 번째 재대전 | 2 | 3 | 3 |
| 3 | 세 번째 재대전 | 2 | 4 | 4 |
| 4 | 네 번째 재대전 | 2 | 4 | 2 |
| 5 | 다섯 번째 재대전 | 2 | 4 | 3 |

Start Round가 마지막 라운드보다 크도록 기존 JSON을 수정해도 로드 시 유효 범위로 보정됩니다.

## 진행도 저장

트레이너 진행도는 플레이어와 NPC UUID 조합별로 저장됩니다.

저장되는 값:

- 승리 클리어 수
- 마지막 라운드
- 마지막 결과
- 마지막 Cobblemon 배틀 ID
- `Once per round` 보상이 실제 성공한 라운드 목록

플레이어 사망·복제 과정에서도 DRM 플레이어 PersistentData로 복사되므로 일반적인 사망으로 초기화되지 않습니다.

### 재적용과 NPC 교체

- 같은 NPC에 다른 Trainer JSON을 Apply: 기존 진행도 유지
- 같은 NPC에서 라운드 순서를 변경 후 재적용: 기존 클리어 수와 보상 라운드 번호가 새 구성에도 그대로 사용됨
- 새로 소환한 NPC에 같은 JSON을 Apply: NPC UUID가 다르므로 별도 진행도
- 다른 플레이어가 같은 NPC에 도전: 플레이어별 별도 진행도

라운드 구조를 크게 바꿀 때는 기존 운영 NPC에 바로 덮기보다 새 NPC에서 먼저 시험하세요.

## Cooldown

Cooldown은 0–1,728,000틱, 정상 20 TPS 기준 최대 약 24시간 범위입니다.

| Scope | 저장 단위 | 결과 |
| --- | --- | --- |
| `Player` | NPC + 플레이어 | 한 플레이어만 기다리며 다른 플레이어는 도전 가능 |
| `NPC` | NPC 공용 | 한 전투가 끝나면 모든 플레이어가 같은 NPC를 기다림 |

쿨다운은 승리뿐 아니라 패배·도주·기타 정상 전투 종료 뒤에도 시작됩니다. Battle Presentation 중 취소돼 실제 배틀이 시작되지 않은 경우에는 시작되지 않습니다.

:::warning 쿨다운은 영구 진행도가 아닙니다
클리어 수와 보상 라운드 기록은 플레이어 PersistentData에 남지만, 쿨다운은 해당 CustomNPCs NPC의 런타임 `tempdata`에 저장됩니다. 서버 재시작이나 NPC 런타임 재생성 후에는 사라질 수 있습니다.
:::

## 권장 구성

### 일반 대화형 트레이너

- Trigger: Interaction
- Battle Positioning: On
- Cooldown Scope: Player
- Rematch: 필요할 때만 On

### 눈이 마주치면 달려오는 트레이너

- Trigger: Vision
- Vision half-angle: 30–45도
- Line of Sight: On
- Reaction Ticks: 10–30
- Chase: On
- Return Home: On

### 보스 방

- Trigger: Radius
- Radius: 방 크기에 맞춤
- Chase: Off 또는 짧은 Stop Distance
- Cooldown Scope: NPC 또는 Player를 운영 목적에 맞게 선택
- 연출 스킵 허용 여부를 반드시 별도 시험

## 테스트 순서

1. Interaction으로 1라운드 전투부터 성공시킵니다.
2. Vision 또는 Radius를 켜고 생존 모드 플레이어로 감지합니다.
3. 벽, 코너, 높이 차이, 좁은 문에서 추적을 시험합니다.
4. Max Distance와 Duration 초과 후 홈 복귀를 확인합니다.
5. 첫 승리·패배·도주 뒤 라운드와 쿨다운을 확인합니다.
6. Fixed, Continue, Loop를 각각 여러 번 승리해 확인합니다.
7. 연출 정상 완료와 스킵에서 Start Delay 차이를 확인합니다.
8. 서버 재시작 후 진행도는 유지되고 쿨다운은 초기화되는지 확인합니다.
9. 같은 JSON을 새 NPC에 적용해 진행도가 분리되는지 확인합니다.
