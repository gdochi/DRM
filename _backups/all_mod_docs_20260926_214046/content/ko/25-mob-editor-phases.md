## 1. 조건을 통과한 패턴 중에서 선택합니다

패턴 목록의 위에서 아래로 차례대로 공격하는 방식이 아닙니다. 먼저 사용할 수 있는 패턴을 추린 뒤, 점수와 우선순위로 선택합니다.

| 설정 위치 | 질문 | 예 |
| --- | --- | --- |
| Core | 지금 이 패턴을 시작해도 되는가? | 거리 0~3, 페이즈 1~2 |
| Score | 가능한 패턴 중 얼마나 선호하는가? | 기본 점수 10, 이상 거리 2 |
| Combat Rules → Manager | 반복·이동·대기를 어떻게 조절하는가? | 같은 패턴 반복 점수 낮추기 |

점수를 높여도 꺼진 패턴, 범위 밖의 타겟, 맞지 않는 페이즈, 남은 쿨다운을 무시하지 않습니다. 패턴·이벤트에 추가 Conditions가 있으면 그 조건도 영향을 줍니다.

## 2. 두 공격이 선택되는지 시험하기

1. [첫 공격](#mob-editor/battleworks-first-attack)을 성공시킵니다.
2. 별도 “전방 찌르기” 패턴을 만들고 [Box 히트박스](#mob-editor/battleworks-hitboxes)를 연결합니다.
3. 두 패턴의 Enabled를 켭니다.
4. 처음에는 둘 다 Min Range `0`, Max Range `2.7`, Priority `10`으로 맞춥니다.
5. 둘 다 Base Score `10`으로 시작합니다.
6. Manager의 Same Pattern Penalty를 `0.5` 정도로 두고 여러 차례 싸웁니다.

**완료 확인:** 조건이 맞는 거리에서 두 공격이 모두 선택됩니다. 몇 번만 보고 정확히 50:50이라고 판단하지 마세요. 거리 보너스와 반복 보정도 선택에 영향을 줍니다.

## 3. 자주 쓰는 조건과 점수

| 항목 | 의미 | 조정 요령 |
| --- | --- | --- |
| Min / Max Range | 시작할 수 있는 수평 거리 | 실제 히트박스와 접근 거리를 함께 맞춤 |
| Max Vertical | 허용 높이 차이 | 높은 절벽 너머의 근접 공격 제한 |
| Min / Max Phase | 허용 페이즈 | 2페이즈 전용이면 2~2 또는 2~16 |
| NPC / Target Health 범위 | 체력 비율 조건 | JSON의 0.5는 50% |
| Base Score | 기본 선택 점수 | 처음에는 같은 값으로 비교 |
| Ideal Distance / Distance Peak | 선호 거리와 거리 보너스 | Ideal Distance를 사용 거리 안에 둠 |
| Missing HP Score | NPC의 잃은 체력에 비례한 가산점 | 체력이 줄수록 자주 쓰는 공격 |
| Phase 2 / Phase 3 Bonus | 특정 페이즈에서의 가산점 | 패턴 허용 범위 자체는 Core에서 설정 |
| Priority | 강한 선택 우선순위 구간 | 일반 공격들은 우선 같은 숫자로 시작 |

Priority를 “가끔 더 쓰게 하는 확률”처럼 사용하지 마세요. 점수 기준을 통과한 높은 우선순위 패턴들이 낮은 우선순위를 배제할 수 있습니다.

## 4. Manager 값 읽기

| 항목 | 의미 | 주의할 점 |
| --- | --- | --- |
| Selection Floor | 최고 점수에 곱한 값보다 낮은 후보 제외 | 최고 20, Floor 0.7이면 14 미만 제외 |
| Same Pattern Penalty | 직전과 같은 패턴의 점수 배율 | 1은 감점 없음, 0은 점수 0 |
| Recent Penalty | 두 번 전 패턴 반복 점수 배율 | 패턴이 적을수록 과도한 제한 주의 |
| Same Role Penalty | 직전과 같은 Role의 점수 배율 | Role은 분류이며 실제 이동을 만들지 않음 |
| Random Factor | 점수에 흔들림 추가 | 0이어도 최종 선택은 점수 가중 무작위 |
| Mobility Urgency / Bonus | 이동을 오래 쓰지 않았을 때 이동 패턴 선호 증가 | Mobility 표시를 실제 설계에 맞춤 |
| Max Stationary / Stationary Penalty | 정지 행동 연속 사용 후 감점 | 후퇴·접근을 적절히 섞을 때 사용 |

JSON의 `avoidImmediateRepeat`만으로 반복이 차단된다고 가정하지 마세요. 현재 선택기는 실제 점수 배율인 Same Pattern Penalty를 사용합니다. 패턴 하나로 시험할 때는 이 값을 1로 두는 편이 이해하기 쉽습니다.

## 5. 비슷해 보이는 네 가지 대기

| 값 | 언제 쓰는가? |
| --- | --- |
| Recovery 단계의 Ticks | 패턴 안의 마지막 동작 길이 |
| Core의 Recovery Delay | 패턴 전체가 끝난 뒤 대기의 최소값 |
| Manager의 Recovery Min / Max | 완료 후 무작위 대기 범위 |
| Core Cooldown / Manager Global Cooldown | 완료한 해당 패턴을 다시 쓰기 전 제한 |

예를 들어 Recovery Delay가 8이고 Manager가 10~14이면 완료 후 대기는 `max(8, 10~14)`, 즉 10~14틱입니다.

Global Cooldown은 모든 패턴을 한꺼번에 잠그는 별도 공용 타이머가 아닙니다. 완료한 패턴의 쿨다운을 `max(그 패턴의 Cooldown, Global Cooldown)`으로 정하는 기준입니다. 다른 패턴이 사용 가능하면 그 패턴이 다음에 선택될 수 있습니다.

## 6. 베기 다음 찌르기 콤보 연결하기

1. 베기 패턴의 **Combo** 속성을 엽니다.
2. 실제 존재하는 찌르기 패턴을 연결합니다.
3. Chance `50%`, Delay `6틱`으로 시작합니다.
4. Manager의 **Max Combo**를 `1` 이상으로 둡니다.
5. 두 패턴 모두 실행 가능한 거리에서 시험합니다.

콤보는 완료 후 연결을 시도합니다. 후속 패턴의 거리·체력·페이즈·시야·쿨다운도 시작 시 다시 확인합니다. 연결선이 있다고 무조건 성공하지 않습니다.

여러 연결의 확률 합은 100% 이하로 맞춥니다. 예를 들어 찌르기 50%, 후퇴 20%면 남은 30%는 콤보 없이 끝날 수 있습니다. Max Combo 0은 콤보를 끕니다. 패시브는 콤보를 소유하거나 콤보의 대상이 될 수 없습니다.

## 7. 체력 50%에서 2페이즈로 전환하기

1. **Combat Rules → Phase / Boss Phases**를 엽니다.
2. 시작 페이즈를 1, 진입 체력 `100%`로 둡니다.
3. 두 번째 페이즈를 추가하고 이름을 “분노”로 정합니다.
4. **Health At or Below (%)**에 `50`을 입력합니다.
5. 강화 공격 패턴의 Min Phase를 `2`로 설정합니다.
6. 기존 베기도 계속 쓰게 하려면 Max Phase를 `2` 이상으로 둡니다.
7. 체력을 절반 아래로 낮춰 강화 공격이 후보에 들어오는지 봅니다.

**화면의 퍼센트 입력은 50, JSON의 enterAtHealthRatio는 0.5**입니다.

페이즈는 한 전투에서 도달한 가장 높은 번호를 유지합니다. 회복해서 체력이 80%가 되어도 2페이즈에서 1페이즈로 내려가지 않습니다. 타겟 상실 후 Combat Reset Delay가 지나면 전투 상태가 초기화되지만, 남은 체력이 낮으면 다음 전투에서 다시 높은 페이즈에 들어갈 수 있습니다.

## 8. 전환 연출 추가하기

1. “분노 시작” 패턴을 만들고 소리·타이틀 같은 짧은 연출을 넣습니다.
2. 이 패턴의 Passive Trigger는 Manager로 둡니다.
3. Min / Max Phase가 2페이즈를 포함하도록 설정합니다.
4. 이동 중에도 시작 가능하게 거리·높이·타겟 조건을 넉넉히 확인합니다.
5. Phase의 **Transition Pattern**에서 “분노 시작”을 고릅니다.

전환 전용 연출이 일반 선택에서도 반복되는 것을 막으려면 Base Score와 모든 가산점을 0으로 둡니다. 전환 실행은 일반 점수 선택과 별도지만 대상·페이즈·거리·체력·추가 조건은 여전히 확인합니다. 현재 전환 실행은 일반 쿨다운과 시야 제한을 우회할 수 있습니다.

한 번에 큰 피해로 여러 체력 기준을 넘으면 중간 연출을 모두 순서대로 실행한다고 가정하지 마세요. 실제 도달한 페이즈의 전환을 시험합니다.
