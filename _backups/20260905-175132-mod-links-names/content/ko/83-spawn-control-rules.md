## 기본 정보

| 필드 | 의미 |
| --- | --- |
| `이름` | 목록에서 읽기 위한 표시 이름 |
| `프로필 ID` | 저장, 진단, 명령어와 개체 추적에 쓰는 고유 ID |
| `우선순위` | 규칙 정렬과 검사 순서를 구성하는 값. 스폰 확률을 대신하지 않음 |
| `활성` | 꺼져 있으면 스케줄러가 이 프로필을 실행하지 않음 |

프로필 ID는 한 활성 문서 안에서 중복될 수 없습니다. 이름은 설명용이고, 운영과 공유에서는 안정적인 ID가 더 중요합니다.

## 월드 조건

모든 조건을 통과해야 후보 위치가 허용됩니다.

| 필드 | 의미 |
| --- | --- |
| `차원` | 비어 있으면 모든 차원. 선택하면 해당 차원 ID만 허용 |
| `바이옴` | 비어 있으면 모든 바이옴. 선택하면 해당 바이옴 ID만 허용 |
| `최소 Y` / `최대 Y` | 후보 블록의 높이 범위 |
| `최소 조도` / `최대 조도` | 후보 위치의 로컬 밝기 범위 0–15 |
| `시작 시간` / `종료 시간` | 월드 시간 0–23999 범위. 시작이 종료보다 크면 자정을 넘어가는 구간 |
| `최소 거리` / `최대 거리` | 후보 위치에서 가장 가까운 살아 있는 비관전자 플레이어까지의 거리 |

예를 들어 `13000`에서 `23000`은 밤 구간입니다. `22000`에서 `2000`처럼 시작 값이 더 크면 자정을 넘어 다음 날 초반까지 허용합니다.

스폰 후보는 이미 로드된 청크에서만 찾습니다. 설정 반경 안에 맞는 좌표가 있어도 청크가 로드되지 않았거나 월드 경계 밖이면 실패합니다.

## 스폰 확률과 무리

| 필드 | 의미 |
| --- | --- |
| `스폰 확률 (0-1)` | 검사 주기마다 통과해야 하는 확률. `0.25`는 25% |
| `검사 간격 틱` | 같은 프로필의 다음 시도까지 기다리는 시간. 20틱은 약 1초 |
| `최소 무리 수` / `최대 무리 수` | 한 번 성공한 시도에서 만들 개체 수 범위 |
| `스폰 반경` | 무작위로 선택한 활성 플레이어 주변 후보 탐색 반경 |
| `위치 탐색 횟수` | 조건에 맞는 로드된 위치를 찾기 위한 최대 후보 검사 수 |
| `배치 방식` | 후보 블록과 유체를 검사하는 방식 |

배치 방식은 다음처럼 동작합니다.

| 방식 | 후보 조건 |
| --- | --- |
| `지상` | 후보 칸이 비어 있고 아래 블록에 충돌 면이 있음 |
| `동굴` | 후보 칸이 비어 있고 하늘이 보이지 않음 |
| `공중` | 후보 칸과 바로 아래 칸이 모두 비어 있음 |
| `수중` | 후보 칸에 유체가 있음 |

확률을 높이거나 간격을 짧게 해도 위치 조건과 개체 수 제한을 통과하지 못하면 생성되지 않습니다. 무리의 두 번째 개체부터는 첫 후보 주변 5블록 이내에서 더 촘촘하게 위치를 찾습니다.

## 개체 수 제한

개체 수 제한은 Dochi's Spawn Control이 생성 표시를 남긴 관리 엔티티를 기준으로 셉니다. 바닐라 원본 스폰 개체나 관리 밖의 명령어 소환 개체를 이 제한에 자동 포함하지 않습니다.

| 필드 | 범위 |
| --- | --- |
| `프로필 제한` | 같은 프로필 ID로 생성된 개체 수 |
| `대상 제한` | 같은 EntityType 또는 같은 클론 대상 키의 개체 수 |
| `플레이어 제한` | 같은 플레이어 문맥을 소유자로 기록한 개체 수 |
| `청크 제한` | 현재 후보 청크 안의 관리 개체 수 |
| `차원 제한` | 현재 차원 안의 관리 개체 수 |
| `서버 제한` | 모든 차원의 전체 관리 개체 수 |
| `공유 그룹 ID` / `공유 그룹 제한` | 여러 프로필이 같은 그룹 ID로 공유하는 합산 제한 |

같은 몹에 여러 프로필을 만들 때 `대상 제한`은 모든 해당 프로필을 함께 묶습니다. 서로 다른 몹도 하나의 총량으로 제한하려면 같은 `공유 그룹 ID`를 사용하세요.

## 생명 주기

| 필드 | 의미 |
| --- | --- |
| `영구 유지` | 생성된 `Mob`에 지속 유지 플래그를 설정하고 무플레이어 자동 제거를 건너뜀 |
| `최대 수명 틱` | 0이면 수명 제한 없음. 값이 있으면 영구 유지 여부보다 먼저 최대 수명 검사 |
| `플레이어 없을 때 제거` | 최대 플레이어 거리 안에 플레이어가 없을 때 제거 타이머 사용 |
| `무플레이어 지연 틱` | 플레이어가 사라진 뒤 실제 제거까지 기다릴 시간 |

이 생명 주기 정책은 이 모드가 생성한 관리 엔티티에만 적용됩니다. 직접 배치한 NPC, 퀘스트 NPC, 관리자 소환 엔티티를 정리하지 않습니다.

## 시작용 예시

### 지상 몹

- 배치 방식: `지상`
- 최소 거리: `24`
- 최대 거리: `96`
- 스폰 반경: `64`
- 위치 탐색 횟수: `8`
- 검사 간격: `200`틱

### 수중 몹

- 배치 방식: `수중`
- 대상 바이옴과 Y 범위를 먼저 넓게 설정
- 현재 위치 검사보다 실제 물 영역 근처에서 시험 생성
- 성공을 확인한 뒤 확률과 개체 수 제한을 낮춰 운영 값으로 조정

:::tip 밸런스 순서
먼저 위치 조건과 배치 방식이 통과하는지 확인하고, 다음으로 확률과 간격, 마지막으로 각종 제한을 조정하면 실패 원인을 찾기 쉽습니다.
:::
