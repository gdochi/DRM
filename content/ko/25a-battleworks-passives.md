## 일반 공격과 패시브의 차이

일반 공격은 Manager가 점수로 고릅니다. 패시브는 **정해진 사건이 일어났을 때 실행을 요청하는 패턴**입니다. “체력 절반 이하에서 한 번 외치기”, “화살에 맞으면 뒤로 이동하기”에 사용합니다.

처음에는 일반 공격이 정상 동작하는 NPC에 패시브 하나만 추가하세요.

## 1. 일반 대기형 트리거 고르기

패턴 선택 → **Core → Passive trigger**에서 다음 중 고릅니다.

| 종류 | 시작 조건 |
| --- | --- |
| Manager | 일반 선택용 패턴 |
| Health Below | 체력이 기준 위에서 기준 이하로 내려감. 처음 관찰할 때 이미 낮은 경우도 해당 |
| Melee Damage | 살아 있는 직접 공격자로부터 양의 피해를 받음 |
| Ranged Damage | 살아 있는 소유자가 있는 투사체·간접 피해를 받음 |
| Any Damage | 그 밖의 유효한 양의 피해도 포함 |

여기서 설명하는 네 가지 기본 패시브는 현재 타임라인을 피해 콜백 안에서 즉시 끊는 방식이 아닙니다. 요청을 대기시키고 시작 가능한 시점에 처리합니다. 0.1.3의 별도 즉시 반응형 트리거는 아래에서 구분합니다.

## 2. 체력 50%에서 한 번 알리는 실습

1. 새 패턴 이름을 “절반 체력 안내”로 정합니다.
2. Passive trigger를 **Health Below**로 고릅니다.
3. 체력 퍼센트 입력을 `50`, Chance를 `100`으로 둡니다.
4. **Once Per Combat**을 켭니다.
5. Busy Policy는 **Queue**, Queue Ticks는 `200`, Trigger Cooldown은 `100`으로 둡니다.
6. Windup `0`, Action `20`, Recovery `10`으로 정합니다.
7. Action 0틱에 Title 액션을 넣고 “이제부터 진짜다!” 같은 짧은 문장을 입력합니다.
8. 타이틀의 수신 대상을 현재 플레이어 타겟으로 설정합니다.
9. Combo 연결은 비워 둡니다.
10. 저장·적용하고 NPC 체력을 50% 아래로 낮춥니다.

**완료 확인:** 일반 공격이 끝나고 조건이 맞으면 안내 패턴이 실행됩니다. 체력이 계속 낮다고 매 틱 반복 실행되지는 않습니다. 플레이어 타겟이 없다면 타이틀 수신 조건부터 확인하세요.

## 3. 입력값 이해하기

| 항목 | 의미 | 실습값을 쓰는 이유 |
| --- | --- | --- |
| Chance | 사건이 발생했을 때 요청 확률 | 100으로 시작해야 실패 원인을 구분하기 쉬움 |
| Minimum Damage | 최소 피해 기준 | 아주 작은 피해를 무시할 때 사용 |
| Trigger Cooldown | 이 반응의 재요청을 제한하는 시간 | 연속 피격으로 반응이 도배되는 것 방지 |
| Queue Ticks | 요청이 대기할 수 있는 최대 시간 | 200이면 약 10초 안에 시작 기회 필요 |
| Queue | 바쁘면 대기 | 공격이 끝난 뒤 반응 |
| Skip | 바쁘면 해당 요청을 건너뜀 | 공격 중 반응을 예약하지 않을 때 |
| Once Per Combat | 성공적으로 시작한 뒤 같은 전투에서는 재사용 제한 | 등장 대사·체력 경고 |

Health Below를 반복 가능하게 했더라도, 다시 체력이 기준 위로 회복한 뒤 아래로 내려오는 변화가 필요합니다. Once Per Combat 기록은 전투 초기화 때 해제됩니다.

## 4. 화살에 맞고 후퇴하기

1. 별도 “원거리 피격 후퇴” 패턴을 만듭니다.
2. Ranged Damage, Minimum Damage `1`, Chance `100`으로 시작합니다.
3. Trigger Cooldown `100`, Queue Ticks `200`, Once Per Combat Off로 둡니다.
4. Action 12틱에 Away 이동을 설정합니다. 실제 설정 방법은 [이동 실습](#mob-editor/battleworks-movement)을 따릅니다.
5. 가까운 거리만 허용한 기존 공격의 Core 조건을 그대로 복사하지 말고, 원거리 피격 시의 거리도 허용합니다.
6. 화살로 맞힌 뒤 공격 종료 후 반응하는지 봅니다.
7. 정상 동작을 확인한 다음 Chance를 `30` 정도로 낮춥니다.

발동 사건을 받았어도 **시작할 때 패턴 조건을 다시 검사**합니다. 화살은 12블록 밖에서 맞았는데 패턴 Max Range가 3이면 후퇴가 시작되지 않을 수 있습니다.

## 5. 여러 기본 패시브가 동시에 생길 때

- NPC당 대기 요청은 최대 8개이며 같은 패턴의 중복 요청은 합쳐집니다.
- 우선순위는 대기 처리와 가득 찬 요청 교체에 영향을 줍니다.
- 페이즈 전환이 먼저 처리됩니다.
- 기본 패시브가 시작되면 예약된 일반 콤보는 취소됩니다.
- 기본 패시브 시작 사이에는 최소 40틱의 공통 간격이 있습니다.
- 가능한 일반 패턴이 있으면 기본 패시브 다음에는 일반 공격 차례를 확보합니다.

따라서 “피해마다 즉시 반격”을 일반 Queue 패시브로 만들면 기대와 다를 수 있습니다.

## 6. 0.1.3의 즉시 반응형 트리거는 별도입니다

현재 소스에는 `hit_count`, `damage_sum`, `evade`, `guard`도 있습니다. 기본 패시브 대기 규칙 전체를 이 유형에 그대로 적용하면 안 됩니다.

| 종류 | 핵심 기준 |
| --- | --- |
| hit_count | 정해진 시간 창의 피해 횟수 |
| damage_sum | 시간 창 안에 누적된 피해량 |
| evade | 유효 피해를 계기로 회피 반응 |
| guard | 정면 각도 조건을 추가한 방어 반응 |

고급 JSON의 `interruptActive`로 진행 중 패턴 중단을 요청하고, `cancelDamage`로 해당 피해 취소를 요청할 수 있습니다. `uninterruptible`인 패턴은 강제 교체를 막을 수 있습니다. `windowTicks`, `threshold`와 페이즈별 확률·기준값도 별도로 쓰입니다.

편집 화면의 공통 패시브 값만으로 모든 고급 동작이 완성되는 것은 아닙니다. 특히 이 경로는 일반 패시브와 별도 대기를 사용하므로 Once Per Combat·Queue Ticks가 똑같이 작동한다고 가정하지 마세요. 고급 트리거는 JSON을 별도 보관하고 실제 피격·중단·피해 취소를 각각 시험합니다.

이 방어 반응과 [Parry 페이지의 미연결 체간·리포스트 설정](#mob-editor/mob-editor-parry)은 서로 다른 기능입니다.

## 동작하지 않을 때

1. 테스트 피해가 취소·0피해·치명타격으로 제외되는 경우인지 확인합니다.
2. Chance를 100으로 올리고 한 가지 트리거만 시험합니다.
3. 패턴 Enabled·타겟·거리·페이즈 조건을 봅니다.
4. Trigger Cooldown과 패턴 자체 Cooldown을 함께 봅니다.
5. Queue가 만료되거나 Skip으로 버려졌는지 봅니다.
6. Once Per Combat을 이미 사용했다면 전투 초기화 후 다시 시험합니다.
7. 콤보·페이즈 전환에 패시브를 연결한 검증 오류가 없는지 확인합니다.
