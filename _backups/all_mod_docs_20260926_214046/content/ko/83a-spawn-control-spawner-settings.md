## 작동 계기와 조건

`Conditions`에서 작동 계기와 추가 조건을 설정합니다. 트리거가 발생해도 플레이어, 시간, 날씨, 레드스톤과 생성 제한을 통과해야 소환합니다.

| 트리거 | 작동 방식 |
| --- | --- |
| `Interval` | 설정한 최소·최대 간격에 따라 반복 시도 |
| 플레이어 진입 | 활성 거리 안에 진입하면 작동. 이탈 거리 밖으로 나갔다가 다시 들어오면 재작동 가능 |
| 이전 무리 정리 | 그 스포너가 소유한 개체가 모두 사라진 뒤 다음 무리 시도 |
| 시간 | 설정한 시간대에 게임 내 하루당 최대 한 번 성공적으로 작동 |
| `Redstone Rising Edge` | 레드스톤 신호가 꺼짐에서 켜짐으로 바뀔 때 시도 |

`Initial delay`는 초기 대기, 최소·최대 간격은 반복 시도 간격입니다. 단위는 틱이며 정상 속도에서 20틱은 1초입니다.

플레이어 필요 여부, 크리에이티브 포함 여부, 최소 인원과 활성·이탈 거리를 함께 확인하세요. `Shared Conditions`는 DRM 공통 조건 편집기를 엽니다. 저장 데이터 비교는 CustomNPCs 스크립트의 플레이어·월드 storeddata를 대상으로 하며, 스코어보드 조건으로 대체되지 않습니다. 공통 조건을 설정했다면 집계할 플레이어가 각각 전체 조건을 통과해야 합니다.

시각은 `0–23999` 범위입니다. 시작이 종료보다 크면 자정을 넘는 구간입니다. 날씨와 레드스톤 필요 상태도 함께 제한할 수 있습니다.

## 소환 수와 위치

| 설정 | 용도 |
| --- | --- |
| `Entities per attempt` | 한 번의 작동에서 시도할 개체 수, 1–64 |
| `Maximum owned entities` | 해당 스포너의 총 보유 개체 제한 |
| `Total spawn limit` | 누적 생성 제한, 0이면 무제한 |
| 반경·수직 범위·최소/최대 Y | 후보 위치를 찾을 공간 |
| 배치 방식 | 지상·공중·물·용암에 맞는 위치 검사 |
| 개체당 위치 탐색 횟수 | 유효한 위치를 찾기 위한 시도 제한 |
| 바이옴 또는 `#tag` | 선택한 바이옴/태그로 제한, 비우면 추가 제한 없음 |
| 조도 종류와 최소·최대 조도 | 종합·블록·하늘 조도 범위 |

불러온 청크 안에서만 후보를 찾으며 강제로 청크를 불러오지 않습니다. 월드 경계와 충돌 검사도 적용됩니다. 소환 수를 높여도 공간이 없거나 제한에 도달하면 그 수를 보장하지 않습니다. 큰 작업은 서버 처리 예산에 따라 나누어 실행될 수 있습니다.

## 파괴 방식

`Destruction`에서 채집 방식 또는 체력 방식을 선택합니다.

| 방식 | 설정과 결과 |
| --- | --- |
| 채집 | 경도와 도구 조건을 설정해 블록 채집으로 제거 |
| 체력 | 최대 체력과 히트박스를 설정해 공격 피해로 파괴 |

설정된 스포너 아이템을 떨어뜨릴지도 선택할 수 있습니다. 체력 방식의 피격 효과는 서버가 실제 피해를 받아들였을 때 발생합니다. 피해 간격 제한 중이거나 거부된 타격은 효과를 다시 재생하지 않습니다.

## 피격 파티클과 사운드

`Effects`에서 피격 파티클 사용 여부, 파티클 타입과 타격당 수를 정합니다. 목록은 현재 인스턴스에 등록된 파티클을 검색해 선택합니다. 추가 데이터가 필요한 파티클은 해당 타입에 맞는 파라미터도 지정해야 합니다.

피격 사운드와 파괴 사운드는 각각 켜거나 끌 수 있습니다. 사운드 ID를 고르고 음량과 피치를 설정하세요. 모드 사운드·파티클을 사용하면 실제 실행 환경에도 그 리소스를 제공하는 모드가 필요합니다.

## 스포너 보스바

보스바를 켜면 스포너 이름과 남은 체력을 표시합니다. 색상도 선택할 수 있습니다. 해당 스포너를 추적하는 플레이어에게 보이며, 스포너가 파괴되거나 추적 대상에서 벗어나면 제거됩니다. 서버 전체 플레이어에게 항상 표시하는 전역 보스바가 아닙니다.

## 참고용 JSON: 70:30 목록에서 3마리 시도

일반 제작은 에디터로 진행하면 됩니다. 다음은 파일을 직접 확인하거나 공유할 때의 간단한 예제입니다. 생략한 값은 기본값으로 채워집니다.

```json
{
  "schemaVersion": 1,
  "name": "Mixed encounter",
  "sources": [
    { "kind": "entity", "id": "minecraft:pig", "weight": 70 },
    { "kind": "entity", "id": "minecraft:cow", "weight": 30 }
  ],
  "activation": { "requirePlayer": true, "includeCreative": true },
  "spawn": { "count": 3, "maxOwned": 9, "maxTotal": 0 }
}
```

`config/dochi_rpg_maker/spawn_control/spawners/examples/mixed.json`에 저장한 뒤 불러옵니다. 크리에이티브 플레이어도 활성 조건에 포함하는 시험용 예입니다. 저장 후 설치된 스포너에 적용해야 작동합니다.
