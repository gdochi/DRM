## 1. 마법은 목록에서 선택하기

1. 필요한 제공 모드와 의존성이 클라이언트·서버에 설치되어 있는지 확인합니다.
2. 패턴을 선택하고 Action 단계에서 **+ Skill**을 누릅니다.
3. 모드 필터에서 원하는 모드를 선택합니다.
4. 스킬 이름이나 ID로 검색하고 **실제로 표시되는 스킬 하나**를 선택합니다.
5. Event Tick을 `0` 또는 준비한 발사 시점으로 둡니다.
6. 이벤트와 액션의 확률을 100%로 둡니다.
7. 스킬 레벨을 낮은 값에서 시작하고 한 번의 시전을 시험합니다.

스킬 액션 하나에는 스킬 하나를 지정합니다. 목록에 없는 임의 ID를 입력해도 스킬이 만들어지지 않습니다. 외부 스킬 파일이나 리소스가 필요한 기능은 해당 자료도 함께 준비해야 합니다.

## 2. 마법이 실패할 때 수치부터 올리지 않기

| 확인 대상 | 이유 |
| --- | --- |
| 제공 모드와 실제 Skill ID | 목록에 없는 스킬은 실행 불가 |
| 타겟 필수·거리·시야 | 액션 시점의 대상 조건이 필요 |
| 스킬 자체 재사용 대기 | BattleWorks 쿨다운과 별도로 적용될 수 있음 |
| 시전자 조건 | 모든 주문이 CustomNPC 시전자와 호환되는 것은 아님 |
| 제공 모드의 options | 스킬마다 지원하는 설정이 다름 |

에디터 미리보기는 실제 외부 주문을 시전하지 않습니다. 월드에서 시험하고 `Battleworks skill failed` 로그가 있으면 그 내용을 확인합니다.

## 3. 피해량을 조절하는 올바른 위치

| 공격 종류 | 피해 조절 |
| --- | --- |
| BattleWorks Hitbox | 공유 Damage × 개별 Damage Multiplier |
| DRM Skill | 스킬 레벨과 제공 모드가 지원하는 옵션 |
| 지원되는 일부 연동 스킬 | 편집 화면에 제공되는 직접 피해 옵션 |
| 관리형 투사체 | 해당 관리형 액션의 Damage |

일반 Skill 액션에 Hitbox의 `damageMultiplier`를 복사해 넣어도 공통 마법 피해 배율로 동작하지 않습니다. 같은 “Damage” 이름이 보여도 어떤 액션의 값인지 확인하세요.

## 4. 연속 시전과 시전 모션

1. 첫 시전 하나가 동작하는 상태를 저장합니다.
2. 다음 발사는 별도 이벤트로 추가하거나 반복 이벤트를 사용합니다.
3. 제공 스킬의 실제 쿨다운보다 너무 빠르게 재요청하지 않도록 간격을 둡니다.
4. 매 발사마다 다른 모션을 쓰려면 각각의 Skill 액션에 다른 Cast Animation을 선택합니다.
5. Cast Animation Ticks가 다음 시전이나 회복 동작을 과도하게 덮지 않게 맞춥니다.

Cast Animation은 **시전에 성공했을 때** 요청됩니다. 실패한 스킬에 모션이 안 나오는 현상은 애니메이션 ID 문제와 구분해야 합니다.

## 5. 공격 소리 추가하기

1. Action의 타격 이벤트 또는 별도 이벤트에 **Sound** 액션을 추가합니다.
2. **Select**에서 등록된 사운드를 고릅니다.
3. **Play / Stop**으로 소리를 확인합니다.
4. Volume과 Pitch를 조정합니다. 처음에는 `1.0 / 1.0`으로 시작합니다.
5. 타격과 같은 틱에 두고 저장·적용합니다.

기본 소리로는 `minecraft:entity.player.attack.sweep`를 사용할 수 있습니다. Sound ID는 `namespace:path` 형식이며 OGG 파일 경로가 아닙니다. 일반 Sound 액션은 NPC 위치의 적대 생명체 소리 범주를 사용합니다.

## 6. 타이틀로 짧은 경고 만들기

1. Windup 0틱에 **Title** 액션을 추가합니다.
2. Title에 “위험!”, Subtitle에 “옆으로 피하세요”를 입력합니다.
3. Audience를 현재 타겟 또는 주변 플레이어로 선택합니다.
4. 주변 전달을 고른 경우 Radius를 정합니다.
5. Fade In `5`, Stay `20`, Fade Out `5`로 시작합니다.
6. 실제 생존 플레이어 화면에서 길이와 겹침을 봅니다.

타이틀은 짧은 화면 안내에 적합합니다. 여러 보스가 동시에 타이틀을 보내면 서로 덮을 수 있으므로 빈도를 줄이고 대사 연출은 별도 팝업 사용도 검토합니다.

## 7. 명령어와 DRM 팝업 연결하기

**Command → Edit command / arguments**에서 편집합니다. 처음에는 아래처럼 결과가 보이는 단순 명령으로 실행 시점을 확인할 수 있습니다.

```text
say BattleWorks timing test
```

Command 액션 입력에서는 앞의 `/` 없이 작성합니다. 실행자는 NPC 또는 타겟으로 고를 수 있습니다.

| 토큰 | 바뀌는 값 |
| --- | --- |
| `@npc` | NPC UUID 문자열 |
| `@target`, `{target}` | 현재 타겟 UUID 문자열 |
| `{player}` | 현재 타겟 플레이어 이름 |
| `{uuid}` | 현재 타겟 플레이어 UUID |

`@npc`와 `@target`은 바닐라 선택자가 아니라 실행 전 치환되는 문자열입니다. 플레이어용 토큰은 타겟이 플레이어여야 합니다.

팝업은 DRM Popup Maker에서 정의와 GUI를 먼저 만들고 실제로 표시되는지 확인한 다음, Command 편집기의 자동 완성과 실제 팝업 이름을 사용해 연결합니다. 다른 배포본의 `combatv1.json`이 자기 서버에도 있다고 가정하지 마세요.

명령 액션은 높은 명령 권한으로 실행됩니다. 대상과 반복 횟수를 확인하고, 매 틱 반복할 필요가 없는 팝업은 한 번만 호출합니다. 팝업이 표시될 때 함께 날 소리는 해당 팝업 정의의 시작 사운드에 연결할 수 있습니다.

## 8. 대사는 가끔, 타격은 항상

같은 이벤트의 Chance를 100%, Hitbox와 Sound를 100%, Command 대사만 20%로 두면 전투 타격은 유지하고 대사만 가끔 실행합니다. 이벤트 자체를 20%로 낮추면 타격까지 대부분 생략될 수 있습니다.

## 9. 전투 BGM 연결하기

1. **Combat Rules → BGM**을 엽니다.
2. Enabled를 켜고 Select에서 실제 등록된 사운드를 고릅니다.
3. Volume `0.7`, Pitch `1.0`으로 시작합니다.
4. Play / Stop으로 소스를 확인하고 저장·적용합니다.
5. 생존 플레이어가 NPC의 타겟이 되게 합니다.
6. 타겟 상실·NPC 사망 후 종료되는지 확인합니다.

BGM은 **현재 플레이어 타겟**에게 반복 재생됩니다. 반경 안의 모든 플레이어에게 자동 전송되는 방식이 아닙니다. 여러 NPC가 같은 플레이어를 노리면 최근 확보된 BGM 소유자가 우선합니다.

플레이어의 **음악 볼륨**이 0이면 들리지 않습니다. 사용자 사운드라면 모든 수신 클라이언트에 리소스가 있어야 합니다. 기본 Minecraft 음악 억제는 별도 **Disable vanilla music** 설정이며 전투 시작·종료와 독립적입니다.

## 연출 확인 순서

스킬 1회 → 타격 소리 → 타이틀 → 팝업 → BGM 순으로 하나씩 추가합니다. 다음은 [Particle Maker](#mob-editor/battleworks-particles)에서 별도 시각 효과를 만드는 방법입니다.
