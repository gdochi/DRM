# Real Armor — 갑옷 아이템 드롭 안내

Real Armor 0.1.5의 갑옷 드롭 안내와 실제 GUI 설정 영상을 추가했다. 한국어·영어·포르투갈어·스페인어·프랑스어의 새 `94-real-armor-drops.md`와 각 언어의 개요·설치 문서를 연결했다. 사이드바에는 **아이템 드롭** 분류를 추가했다. 이전 0.1.4 방어 설정 이미지는 촬영 버전을 그대로 표시한다.

## 소스 확인과 안내 범위

- `[COMMON] Dochi Real Armor`와 `[26.3] Dochi Real Armor`의 현재 문서·저장·런타임·프로토콜·에디터 소스와 배포 JAR 5종을 확인했다. 경로와 SHA-256은 `evidence/armor-drops-20261108/source-audit.json`에 있다. 모드 소스와 배포 JAR은 변경하지 않았다.
- 내구도가 실제로 줄거나 방어구가 파괴될 때 손상된 장비별로 각 드롭을 한 번씩 독립 판정한다. 사망 보상으로 설명하지 않는다. 0–100% 확률, 수량 1–64, 항목 최대 16개, 아이템 데이터·스택 크기, 실제 월드 저장 위치를 안내한다.
- Save/Save As는 이름 있는 세트만 저장하고 Load는 초안만 연다. Apply가 저장 세트로 월드 활성 규칙 전체를 교체하며, 한 월드에 한 세트만 활성화된다. Unapply는 저장 세트를 남긴다. 미리보기는 정적인 갑옷 거치대다.
- 기존에 게시한 작성자 기록 `content/changelogs/dochi-real-armor/0.1.5.json`을 현재 `[LOG] Change Log/리얼아머/0.1.5.md`와 맞췄다. 게시 날짜·환경·공개 파일 검증 목록은 보존했다. 문서·촬영 도구 변경은 모드 릴리스 항목으로 추가하지 않았다.

## 실제 GUI 영상

- 사용자에게 실행 허가를 받은 후 다른 작업의 게임이 종료되기를 기다려 **한 인스턴스만 한 번** 실행했다. `armor-drops-neo1211-en-01`의 별도 월드, NeoForge 1.21.1 / Real Armor 0.1.5 / DRM 0.3.1 / DNPC 0.1.3을 사용했다. 힙 상한은 기존 3GB다. 다른 작업의 게임과 사용자 월드는 수정하거나 종료하지 않았다.
- 원본 828개 프레임, 약 41.43초. 실제 Armor Drop Editor에서 철 흉갑과 철 조각을 검색·선택하고 확률 100%·수량 1–3을 입력한 뒤 Save As → Save → Apply를 사용했다. 촬영 도구가 네이티브 위젯의 클릭·입력 경로를 사용했으며 합성 UI나 수동 마우스 촬영으로 표현하지 않는다.
- 실제 서버 확인: Save 후 비활성·revision 1, Apply 후 활성·revision 2. 저장된 아이템 ID·확률·최소/최대 수량과 활성 문서를 확인했다. `armor-drops-saved.json`, `armor-drops-applied.json`을 보존했다. 실제 전투·월드 드롭 생성이나 다른 로더의 인게임 검증은 이번 촬영 범위가 아니다.
- 원본 PNG의 타임스탬프로 1280×720 / 20fps / BT.709 무음 MP4·WebM을 만들었다. 프레임 보간이나 GIF 변환은 사용하지 않았다. 두 영상의 모든 프레임 디코딩과 포스터를 확인했다. 게시 영상은 `src/media/guides/armor-drops-015-20261108/`에 있다.
- 인코딩 영수증·원본 프레임 해시·대표 프레임·접촉 시트·실제 환경과 JAR 해시·클라이언트 종료 로그를 `evidence/armor-drops-20261108/`에 보존한다.
- 게임은 촬영 후 정상 종료됐다. 촬영 래퍼는 완료 JSON을 Windows cp949 콘솔에 출력하는 단계에서 인코딩 오류가 났으나, 게임 종료 코드 0·finished 표식·영상·서버 검증 파일은 정상이다. 래퍼의 콘솔 출력만 ASCII JSON으로 수정했으며 게임을 재실행하지 않았다. 초기 컴파일은 성공했다.
