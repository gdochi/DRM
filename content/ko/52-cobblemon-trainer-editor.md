## 에디터의 역할

`Cobblemon Editor`는 CustomNPCs NPC가 사용할 Cobblemon 전투 데이터를 만드는 제작자 화면입니다. 플레이어가 보는 배틀 화면이 아니라, 서버 JSON에 상대 파티와 조우 규칙을 저장하는 편집 도구입니다.

한 문서는 다음 두 유형 중 하나입니다.

| 유형 | 저장 폴더 | 기능 |
| --- | --- | --- |
| `Trainer` | `config/dochi_rpg_maker/cobblemon/trainers/` | 파티, 전투 포맷, AI, 최대 16라운드, 재대전, 조우, 조건, 보상 |
| `Pokemon Itself` | `config/dochi_rpg_maker/cobblemon/pokemon_itself/` | 지정한 한 마리의 포켓몬과 벌이는 PVE 전투와 NPC 포켓몬 외형 |

유형을 바꾸면 `Load`와 `Save As`가 사용하는 폴더도 바뀝니다. 폴더와 문서의 `battleType`이 맞지 않으면 에디터가 파일을 거부합니다.

## 상단 작업 버튼

| 버튼 | 기능 | 주의점 |
| --- | --- | --- |
| `Editors` | DRM 에디터 선택 화면으로 돌아갑니다. 대상 NPC에 적용하려면 이 흐름으로 돌아가 적용 대상을 선택합니다. | 저장하지 않은 값은 먼저 저장하세요. |
| `Create New` | 비활성화된 새 초안을 만듭니다. | `Enabled`를 직접 켜야 합니다. |
| `Load` | 현재 전투 유형의 서버 폴더에서 JSON을 불러옵니다. | Trainer와 Pokemon Itself 폴더는 서로 분리됩니다. |
| `Save` | 현재 파일에 덮어씁니다. | 기본 파일을 직접 수정하기보다 사용자 파일을 사용하세요. |
| `Save As` | 새 상대 경로로 저장합니다. | 첫 작업은 `custom/...` 경로를 권장합니다. |
| `Reset` | 현재 편집값을 기본값으로 되돌립니다. | 저장하지 않은 변경은 사라집니다. |
| `Close` | 에디터를 닫습니다. | 닫는 것만으로 NPC에 적용되지 않습니다. |

`Save`와 `Save As`는 서버 JSON을 저장할 뿐입니다. NPC는 저장 파일을 실시간으로 참조하지 않으므로 파일을 수정한 뒤 대상 NPC에 다시 `Apply`해야 합니다.

## 화면 구조

왼쪽의 큰 카테고리는 `Pokemon Party`와 `Trainer`입니다. `Trainer` 안에는 다시 다음 탭이 있습니다.

| 탭 | 편집 내용 | 서버에서 사용되는 시점 |
| --- | --- | --- |
| `General` | 활성화, 이름, 전투 유형, Battle Presentation | NPC 적용 후 전투 요청을 받을 때 |
| `Encounter` | Interaction/Vision/Radius, 추적, 위치 정렬, 쿨다운 | 플레이어를 찾고 배틀을 예약할 때 |
| `Detection FX` | 감지 마커, 색, 크기, 사운드, 반응 시간 | Vision/Radius가 새 대상을 잡았을 때 한 번 |
| `Rounds` | 라운드 순서, 포맷, AI, 시작 지연, 재대전 | 현재 플레이어의 클리어 수로 상대 라운드를 고를 때 |
| `Conditions` | 현재 선택 라운드의 도전 조건 | 자동 감지와 실제 배틀 시작 직전 |
| `Rewards` | 현재 선택 라운드의 승리 보상 | 승리가 확정된 뒤 |

`Pokemon Itself`로 바꾸면 Trainer 전용 화면은 비활성화되고 `Pokemon Party`에서 한 마리만 편집합니다. Trainer에서 Pokemon Itself로 전환할 때는 현재 선택한 파티 슬롯이 한 마리 데이터의 출발값이 됩니다.

## General

| 필드 | 기능 |
| --- | --- |
| `Enabled` | 꺼져 있으면 JSON과 NPC 데이터가 있어도 이 트레이너 전투를 시작하지 않습니다. |
| `Name` | 에디터와 런타임 메시지에 사용할 트레이너 문서 이름입니다. NPC의 월드 표시 이름과는 별개입니다. |
| `Battle Type` | `Trainer` 또는 `Pokemon Itself`를 선택합니다. 저장 폴더와 편집 화면이 함께 바뀝니다. |
| `Battle Presentation` | `battle_presentations/` 기준의 연출 파일 경로입니다. 파일 내부 Name이 아니라 저장 경로로 연결합니다. |

연출 경로가 비었거나 파일을 읽지 못하면 전투 유형에 맞는 기본 프리셋을 사용합니다. 연출 파일을 수정해도 트레이너 JSON의 경로가 같다면 트레이너 문서를 다시 저장할 필요는 없지만, NPC에 복사된 트레이너 데이터 자체를 바꿨다면 다시 적용해야 합니다.

## 파티 화면

Trainer는 라운드마다 1–6마리, Pokemon Itself는 한 마리를 사용합니다. Trainer 파티 화면 위쪽에는 현재 편집 중인 `Round N/전체`가 표시되고 이전·다음 라운드 버튼으로 이동할 수 있습니다.

Trainer 파티에서 할 수 있는 작업:

- `Add Pokémon`: 현재 라운드에 슬롯을 추가합니다. 최대 6마리입니다.
- `Remove Pokémon`: 선택한 슬롯을 삭제합니다. 라운드에는 최소 한 마리가 남아야 합니다.
- 파티 행 드래그: 실제 파티 순서를 바꿉니다. 첫 슬롯은 상대 선두이자 트레이너가 들고 있는 볼 연출의 기준입니다.
- 기술 행 드래그: 기술 순서를 바꿉니다.
- `Previous` / `Next`: 다른 라운드의 파티로 이동합니다. 이동 전에 현재 입력값이 현재 라운드에 저장됩니다.
- `Back to Rounds`: `Rounds` 탭으로 돌아갑니다.

라운드마다 파티 목록이 별개입니다. 2라운드의 이상해씨를 리자몽으로 바꿔도 1라운드는 바뀌지 않습니다.

## 포켓몬 필드

| 필드 | 저장·생성 동작 |
| --- | --- |
| `Species` | 포켓몬 종 ID입니다. `cobblemon:`이 없으면 자동으로 붙습니다. 존재하지 않는 종이면 상대 생성에 실패할 수 있습니다. |
| `Form` | 비우면 종의 기본 폼입니다. 입력하면 해당 폼 이름을 Cobblemon 생성 속성에 전달합니다. |
| `Aspects` | 쉼표로 여러 Aspect를 저장합니다. 앞뒤 공백과 빈 항목은 제거되고 중복은 정리됩니다. |
| `Shiny` | 실제 배틀 포켓몬의 이로치 여부입니다. NPC 렌더의 `Shining` 효과와는 다른 값입니다. |
| `Level` | 1–100으로 제한됩니다. |
| `Nature` | 비우면 생성 기본값을 사용하고, 지정하면 해당 성격을 요청합니다. |
| `Ability` | 비우면 생성 기본값을 사용하고, 지정하면 해당 특성을 요청합니다. |
| `Moves` | 중복 없는 최대 4개입니다. 비어 있으면 생성 후 레벨 기반 기술을 초기화합니다. |
| `Poké Ball` | 유효한 Cobblemon 볼 ID를 사용합니다. 잘못된 값은 `cobblemon:poke_ball`로 대체됩니다. |
| `Held Item` | 유효한 아이템 ID를 지닌 도구로 전달합니다. 빈 값은 지닌 도구 없음입니다. |

종·기술 선택기의 세대와 타입 필터는 검색 결과만 좁힙니다. “1세대만 사용” 같은 런타임 제한을 저장하는 기능은 아닙니다.

### 파티 구성 시 주의점

- `Doubles`는 최소 2마리, `Triples`는 최소 3마리의 유효한 포켓몬을 준비하는 편이 안전합니다.
- AI Skill이 높아도 없는 기술을 만들거나 잘못된 종·특성·도구를 고쳐 주지 않습니다.
- 첫 슬롯의 볼이 배틀 연출과 전투 중 트레이너 손에 표시됩니다.
- 모든 슬롯의 종 생성이 실패하면 전투는 시작되지 않습니다.
- 기술을 비워 자동 구성할 때와 기술 4개를 고정할 때의 난이도가 크게 달라질 수 있습니다.

## 라운드의 구성

Trainer 문서는 최소 1개, 최대 16개 라운드를 가집니다. 각 라운드에는 다음 데이터가 한 묶음으로 들어갑니다.

- `Singles`, `Doubles`, `Triples` 포맷
- AI Skill 0–5
- 시작 지연 0–1200틱
- 1–6마리 파티
- 조건 그룹과 최대 32개 조건
- 보상 모드·지급 정책과 최대 32개 보상

라운드 행을 드래그해 순서를 바꾸면 파티·조건·보상까지 라운드 전체가 함께 이동합니다. 순서 변경 후에는 재대전의 `Start Round`가 여전히 의도한 라운드를 가리키는지 다시 확인하세요.

## 라운드 추가·삭제의 정확한 동작

`Add Round`는 완전히 빈 라운드를 만들지 않습니다. 현재 선택 라운드에서 다음 값을 복제합니다.

- 전투 포맷
- AI Skill
- 파티 전체

새 라운드에서 다음 값은 초기화됩니다.

- `Battle start delay`: `0`
- Conditions: 빈 기본 그룹
- Rewards: 빈 기본 그룹

추가 직후 새 라운드가 선택됩니다. 따라서 단계별 강화 파티를 만들 때는 1라운드를 완성한 뒤 추가하고, 복제된 파티에서 레벨·기술·멤버만 바꾸는 방식이 빠릅니다.

`Remove Round`는 선택 라운드 전체를 삭제합니다. 그 라운드의 파티·조건·보상도 같이 없어지며 최소 1라운드는 삭제할 수 없습니다. 삭제 후에는 같은 위치의 다음 라운드 또는 마지막 남은 라운드가 선택됩니다.

## 라운드 선택과 편집값 저장

`Conditions`와 `Rewards` 화면 위에는 라운드 번호 선택 막대가 있습니다. 번호를 바꾸면 현재 필드가 기존 라운드에 먼저 저장되고 선택 라운드가 바뀝니다. 조건·보상 선택 행과 스크롤 위치는 새 라운드 기준으로 초기화됩니다.

라운드가 많을 때는 다음을 항상 확인하세요.

1. 화면 상단의 `Round N/전체`
2. Rounds 목록에서 강조된 행
3. Conditions/Rewards의 선택 라운드 번호
4. 파티 화면의 라운드 제목

서로 다른 라운드를 편집했다고 느끼는 대부분의 실수는 이 번호를 확인하지 않아 발생합니다.

## 전투 포맷

| 포맷 | 상대가 동시에 내는 수 | 권장 사용 |
| --- | ---: | --- |
| `Singles` | 1 | 일반 트레이너, 첫 테스트 |
| `Doubles` | 최대 2 | 조합 기술과 지원형 포켓몬을 쓰는 전투 |
| `Triples` | 최대 3 | 충분한 파티와 넓은 전술 구성을 갖춘 보스 전투 |

실제 배틀은 Cobblemon의 9세대 전투 규칙으로 시작됩니다. 플레이어의 현재 선두 포켓몬 UUID를 기준으로 선두 순서를 잡습니다. 연출 도중 선두 포켓몬을 사용할 수 없게 되면 배틀 시작 전 검증에서 취소될 수 있습니다.

## AI Skill

AI Skill은 능력치 배율이 아니라 Cobblemon `StrongBattleAI`의 고급 행동과 교체 판단 확률입니다.

| AI Skill | 고급 판단 | 교체 판단 |
| --- | ---: | ---: |
| 0 | 0% | 0% |
| 1 | 20% | 0% |
| 2 | 40% | 0% |
| 3 | 60% | 20% |
| 4 | 80% | 60% |
| 5 | 100% | 100% |

AI Skill 5도 항상 최선의 수를 보장하는 절대 난이도 설정은 아닙니다. 파티 상성, 기술 구성, 레벨, 지닌 도구와 전투 포맷을 함께 설계해야 합니다.

## Battle start delay

`Battle start delay`는 0–1200틱입니다. 정상 재생에서는 다음처럼 계산됩니다.

```text
배틀 시작 예정 시각 = 현재 시각 + 연출 Duration + 현재 라운드 Start Delay
```

예를 들어 연출이 48틱이고 시작 지연이 20틱이면 약 68틱 후 서버가 최종 검증과 배틀 시작을 시도합니다.

`Skippable` 연출을 플레이어가 건너뛰면 서버는 예정 시각을 기다리지 않고 즉시 최종 검증으로 넘어갑니다. 즉, 남은 연출 시간뿐 아니라 아직 남은 `Battle start delay`도 건너뜁니다. 반드시 기다려야 하는 연출이라면 `Skippable`을 끄세요.

## 3라운드 트레이너 제작 예시

### 1. 첫 라운드

1. `Use Default`를 엽니다.
2. `Enabled`를 켜고 이름을 정합니다.
3. `Rounds`에서 1라운드를 `Singles`, AI 2로 둡니다.
4. `Edit this round's party`에서 2마리 파티를 만듭니다.
5. 저장·적용해 첫 전투가 정상 시작되는지 먼저 확인합니다.

### 2. 강화 라운드

1. 1라운드를 선택하고 `Add Round`를 누릅니다.
2. 복제된 파티의 레벨·기술을 올리고 한 마리를 교체합니다.
3. AI를 3으로 올립니다.
4. 2라운드 Conditions와 Rewards가 비어 있는지 확인합니다.

### 3. 최종 라운드

1. 2라운드를 선택한 상태에서 다시 `Add Round`를 누릅니다.
2. 최종 파티를 완성하고 AI를 5로 설정합니다.
3. 3라운드에 전용 조건과 보상을 추가합니다.

### 4. 재대전

1. `Rematch`를 켭니다.
2. `Start Round`를 2로 설정합니다.
3. `Round Mode`를 `Continue`로 설정합니다.
4. 첫 도전은 1라운드, 첫 승리 뒤 재대전은 2라운드, 다음 승리는 3라운드, 이후는 3라운드가 됩니다.

## 저장과 NPC 적용

1. 기본 또는 샘플 파일을 불러옵니다.
2. `Save As`로 `custom/gym/forest_leader.json` 같은 사용자 경로에 저장합니다.
3. `Editors`로 돌아갑니다.
4. `Dochi RPG Maker Core`로 대상 CustomNPCs NPC를 엽니다.
5. 적용 대상에서 `Cobblemon Trainer`를 선택합니다.
6. 저장한 파일을 선택하고 `Apply`합니다.
7. 코어 아이템을 내려놓고 Main Hand와 Off Hand를 모두 비웁니다.
8. NPC를 우클릭하고 확인 화면에서 전투를 수락합니다.

저장한 JSON을 다시 편집한 뒤에는 같은 NPC에 다시 `Apply`해야 합니다. 재적용은 기존 플레이어의 클리어 수와 라운드별 보상 기록을 자동 초기화하지 않습니다. 완전히 새 진행도로 시험하려면 새 UUID를 가진 테스트 NPC를 사용하는 것이 가장 안전합니다.

## 전투 시작 전 서버 검사

플레이어가 전투를 요청하면 서버는 대략 다음 순서로 검사합니다.

1. NPC와 플레이어가 유효하고 허용 거리 안인지 확인
2. 문서가 활성화됐는지 확인
3. NPC가 다른 전투·연출에 예약되지 않았는지 확인
4. 플레이어가 이미 Cobblemon 배틀 중인지 확인
5. 클리어 수로 재대전 가능 여부와 현재 라운드 계산
6. 쿨다운 검사
7. 현재 라운드 조건 검사
8. 플레이어의 유효한 선두 포켓몬 확인
9. NPC·플레이어 예약, 위치 정렬, 트레이너 잠금, 선두 볼 표시
10. 연출과 시작 지연 뒤 거리·선두 포켓몬·조건을 다시 검사
11. 상대 파티 생성 후 Cobblemon 배틀 시작

중간 검사가 실패하면 예약과 트레이너 볼 표시를 복구하고 전투를 시작하지 않습니다.

## 제작 완료 점검

- 모든 라운드에 유효한 포켓몬이 1마리 이상 있는가
- Doubles/Triples에 필요한 파티 수가 있는가
- 라운드 추가 후 조건과 보상을 다시 만들었는가
- 라운드 순서를 바꾼 뒤 Start Round를 다시 확인했는가
- 첫 라운드과 재대전 라운드가 의도한 순서로 선택되는가
- 승리·패배·도주를 각각 시험했는가
- 연출 정상 완료와 스킵을 각각 시험했는가
- JSON 저장 후 NPC에 다시 Apply했는가
