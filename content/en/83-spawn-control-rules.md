This page describes **natural-spawn profiles**. For placed spawners, use the [Spawner Editor guide](#dochi-spawn-control/dochi-spawn-control-spawner). Natural-spawn `Spawn Chance (0-1)` is separate from relative chances in a spawner target list.

## Identity

| Field | Meaning |
| --- | --- |
| `Name` | Human-readable list label |
| `Profile ID` | Unique ID used for storage, diagnostics, commands, and entity tracking |
| `Priority` | Organizes rule ordering and checks; it is not a replacement for spawn chance |
| `Enabled` | Disabled profiles are skipped by the scheduler |

Profile IDs must be unique inside one active document. The display name is descriptive; the stable ID matters for operations and sharing.

## World Conditions

Every applicable condition must pass for a candidate position.

| Field | Meaning |
| --- | --- |
| `Dimensions` | Empty allows every dimension; selected IDs form an allowlist |
| `Biomes` | Match any included ID/tag; empty inclusion allows all. Exclusions take priority |
| `Minimum Y` / `Maximum Y` | Candidate block height range |
| `Minimum Light` / `Maximum Light` | Local brightness range from 0 to 15 |
| `Start Time` / `End Time` | World time from 0 to 23999; an inverted range crosses midnight |
| `Minimum Distance` / `Maximum Distance` | Distance from the candidate to the nearest living, non-spectator player |

For example, `13000` through `23000` is a night range. `22000` through `2000` crosses midnight and allows the end of one day plus the start of the next.

Candidates are searched only in already-loaded chunks. A matching coordinate outside loaded chunks or beyond the world border is rejected.

## Spawn Rate and Group

| Field | Meaning |
| --- | --- |
| `Spawn Chance (0-1)` | Probability roll at each eligible interval; `0.25` means 25% |
| `Interval Ticks` | Delay before this profile's next attempt; 20 ticks is about one second |
| `Minimum Group` / `Maximum Group` | Number of entities requested by one successful attempt |
| `Spawn Radius` | Candidate-search radius around a randomly selected active player |
| `Position Attempts` | Maximum candidate checks used to find a valid loaded location |
| `Placement` | Block and fluid policy for candidate positions |

| Placement | Candidate rule |
| --- | --- |
| `Surface` | Candidate block is empty and the block below has a collision surface |
| `Cave` | Candidate block is empty and cannot see the sky |
| `Air` | Candidate block and the block below are both empty |
| `Water` | Candidate block contains fluid |

A high chance or short interval cannot bypass world conditions or population caps. Additional group members search within five blocks of the first successful candidate.

## Population Caps

Caps count entities marked and tracked as generated by Dochi's Spawn Control. They do not automatically count ordinary native-spawn entities or unmanaged command summons.

| Field | Scope |
| --- | --- |
| `Profile Cap` | Entities created by the same profile ID |
| `Target Cap` | Entities with the same EntityType or clone target key |
| `Player Cap` | Entities recorded under the same player context |
| `Chunk Cap` | Managed entities in the candidate chunk |
| `Dimension Cap` | Managed entities in the candidate dimension |
| `Server Cap` | Managed entities across all dimensions |
| `Shared Group ID` / `Shared Group Cap` | Combined limit shared by profiles with the same non-empty group ID |

When one target has several profiles, Target Cap combines those profiles. Use a shared group when different targets must share one broader population limit.

## Lifecycle

| Field | Meaning |
| --- | --- |
| `Persistent` | Marks generated mobs as persistence-required and skips no-player cleanup |
| `Maximum Lifetime Ticks` | `0` disables age cleanup; a positive maximum is checked even for persistent profiles |
| `Despawn Without Player` | Starts cleanup when no player remains within Maximum Distance |
| `No-player Delay Ticks` | Delay between losing nearby players and removal |

Lifecycle policy applies only to entities created and marked by this mod. It does not clean up hand-placed NPCs, quest NPCs, or administrator summons.

## Baseline examples

### Land mob

- Placement: `Surface`
- Minimum Distance: `24`
- Maximum Distance: `96`
- Spawn Radius: `64`
- Position Attempts: `8`
- Interval: `200` ticks

### Aquatic mob

- Placement: `Water`
- Begin with broad biome and Y ranges
- Test near a real body of water
- Reduce chance and caps to production values only after placement succeeds

:::tip Balancing order
Verify world conditions and placement first, then tune chance and interval, and adjust caps last. This keeps failed attempts easier to diagnose.
:::

## Structure filters and squads

In 0.1.5, Locations and guard squad offers included/excluded biome and structure IDs and tags. Structures use the registered bounds of existing generated structures; the filter does not recognize hand-built buildings or generate new structures. Dimension, time, light, distance and existing population caps still apply.

An enabled squad uses explicit member counts instead of Minimum/Maximum Group, with at most 64 entities in total. One probability roll prepares the entire composition; every member needs valid space, conditions and caps before the group is inserted together. See the [guard guide](#dochi-spawn-control/spawn-control-guards) for one-group-per-structure limits and the delay after the last member is removed.
